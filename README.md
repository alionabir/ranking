# AMML Ranking Competition 2026 — Jina reranker

## Финальное решение

Файлы в корне репозитория: `solution.ipynb`, `requirements.txt`, `README.md`. Ноутбук содержит **только финальный пайплайн**: загрузка данных соревнования, разделение по `query_id`, дообучение `jinaai/jina-reranker-v2-base-multilingual` с бинарной кросс-энтропией, валидация, исправление mojibake **только в test после обучения**, получение `submission_encoding_fixed.csv`. Внешние размеченные датасеты не используются; используется публично доступная предобученная модель, которую мы дообучаем на данных соревнования.

**Исходное окружение:** Kaggle, Linux, NVIDIA Tesla T4, Python 3.13.16, PyTorch 2.11.0+cu130, Transformers 5.20.2, tokenizers 0.23.3. `requirements.txt` содержит зафиксированные прямые зависимости, но полное воспроизведение CUDA-окружения зависит от драйвера и способа установки PyTorch.

## Как запустить

1. Создать окружение Python 3.13, установить `python -m pip install -r requirements.txt` (для GPU — совместимую CUDA-сборку PyTorch согласно официальной инструкции).
2. Положить `train.csv`, `test.csv`, `sample_submission.csv` в папку `data/` рядом с ноутбуком **или** задать переменную окружения `AMML_DATA_DIR` с путём к этим файлам. На Kaggle ноутбук автоматически ищет датасет в `/kaggle/input`.
3. Запустить все ячейки `solution.ipynb` по порядку в чистом ядре. Необходим интернет для загрузки модели с Hugging Face; `trust_remote_code=True` запускает код доверенного репозитория модели.
4. Забрать `outputs/submission_encoding_fixed.csv` (на Kaggle: `/kaggle/working/outputs/`).

Валидация: при наличии необязательного `valid_fixed.csv` с колонкой `id` используется исходное разбиение; иначе — `GroupShuffleSplit(test_size=0.20, random_state=42)` по `query_id`. Исходный файл с ID валидации в комплекте **не представлен**; это ограничивает возможность гарантировать точное совпадение исторических метрик. В репозиторий достаточно положить ровно три запрошенных файла; датасет подаётся извне.

## Почему кодировку исправляем после обучения

В тестовом наборе обнаружено **72 строки** поля `text` с ошибкой кодирования UTF-8 как Windows-1251 (например, `РљР»Рµ...` → нормальная кириллица). В `query` и `title` в этом эксперименте исправлений не было. Функция пытается `encode('cp1251').decode('utf-8')`, принимает замену только при уменьшении числа характерных артефактов. Никакие метки тестовых данных не используются. Исправление применяется только при подготовке test для инференса, **не** при обучении. Попытка переобучить модель на исправленном train дала менее высокий Public LB.

## Гиперпараметры и ограничения

Модель: `jinaai/jina-reranker-v2-base-multilingual`; вход: пара `(query, 'Title: ...\nPassage: ...')`; max length 768; batch 2; gradient accumulation 8; 1 эпоха; AdamW LR 1e-5, weight decay 0.01; warmup 6%; BCEWithLogitsLoss; FP16 autocast на CUDA; seed 42. Эти настройки собраны из сохранившихся ячеек исходного экспериментального ноутбука; в его последнем фрагменте некоторые параметры не были определены самостоятельно. В зависимости от фактического состояния ядра исторического запуска возможны расхождения.

**Проверка:** структура и синтаксис ноутбука проверены при сборке; полный GPU-прогон с загрузкой весов, обучение и точное совпадение Kaggle LB в среде подготовки файлов не проверялись. Перед отправкой обязательно выполнить чистый прогон в окружении из `requirements.txt`, сохранить лог версий и сверить результат с контрольным submission. Публичную ссылку на репозиторий необходимо создать самостоятельно и проверить доступ без авторизации.
