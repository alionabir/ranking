# AMML Ranking Competition 
Финальное решение
Для задачи ранжирования русскоязычных документов использовалась модель jinaai/jina-reranker-v2-base-multilingual, дообученная на данных соревнования.
В файле solution.ipynb представлен полный пайплайн: загрузка данных, разделение на обучающую и валидационную выборки, дообучение модели, оценка качества и формирование итогового submission.
В финальном варианте также используется исправление ошибок кодировки в тестовых текстах. Обработка выполняется после обучения модели, непосредственно перед инференсом.
Лучший результат на Public Leaderboard составил 0.960620 
Запуск решения
Обучение и инференс проводились в Kaggle на Linux с видеокартой NVIDIA Tesla T4. Использовались Python 3.13.16, PyTorch 2.11.0+cu130 и Transformers 5.20.2.
Ноутбук предусматривает запуск как в Kaggle, так и на локальном компьютере с Windows или Linux.
Для установки зависимостей:
python -m pip install -r requirements.txt
Файлы train.csv, test.csv и sample_submission.csv необходимо поместить в папку data рядом с ноутбуком либо указать их расположение через переменную окружения AMML_DATA_DIR. При запуске в Kaggle данные автоматически ищутся в /kaggle/input.
После установки зависимостей и подготовки данных все ячейки ноутбука выполняются последовательно.
Обучающая и валидационная выборки формируются с помощью GroupShuffleSplit . Разделение проводится по query_id, чтобы документы одного запроса не попадали одновременно в обучение и валидацию.
После инференса формируется файл submission, который сохраняется в папку outputs.
Для загрузки предобученной модели необходим доступ к Hugging Face.
Ход экспериментов
1. BGE Reranker
Первым подходом стало дообучение BGE Reranker на парах «запрос –документ».
Проводились эксперименты с количеством эпох, функцией потерь и анализом сложных запросов. Отдельно рассматривались случаи, когда модель неправильно определяла наиболее релевантный документ.
На одном из валидационных разбиений удалось получить NDCG@10 около 0.938.
Несмотря на достаточно высокое качество, следующим этапом стало тестирование другой модели – Jina Reranker
2. Jina Reranker
Для дальнейших экспериментов использовалась модель jinaai/jina-reranker-v2-base-multilingual.
Модель получает запрос и документ и предсказывает оценку их релевантности. Для дообучения использовалась бинарная кросс-энтропия (BCEWithLogitsLoss).
Входной текст документа формировался из заголовка и основного текста:
Title: ...
Passage: ...
Первый успешный эксперимент с Jina (E13) показал результат 0.956735 на Public Leaderboard.
Следующая версия с одной эпохой обучения получила 0.957853. Именно она стала основой для финального решения.
3. Исправление кодировки
При анализе тестовой выборки обнаружились ошибки кодировки в некоторых русскоязычных текстах.
Например, вместо нормальной кириллицы встречались последовательности вида:
РљР»РµРѕРїР°С‚СЂР°
Такие ошибки возникают при неправильной интерпретации байтов UTF-8 в другой кодировке.
Для восстановления текста использовалось преобразование:
text.encode("cp1251").decode("utf-8")
Исправление применялось только в тех случаях, когда после преобразования уменьшалось количество характерных признаков повреждённой кодировки.
В тестовой выборке было исправлено 72 строки в столбце text. В столбцах query и title изменений не потребовалось.
После исправления кодировки был проведён повторный инференс с теми же весами обученной Jina. Результат на Public Leaderboard вырос с 0.957853 до 0.960620.
Это стало лучшим результатом среди проведённых экспериментов.
4. Обучение на данных с исправленной кодировкой
Дополнительно проводился эксперимент с исправлением кодировки в обучающей выборке.
После обработки текстов модель Jina была заново дообучена с теми же основными гиперпараметрами.
Результат составил 0.959783, что немного ниже предыдущего значения.
Разница не обязательно связана только с исправлением кодировки, поскольку повторное обучение может давать отличающиеся результаты из-за случайной инициализации и особенностей вычислений.
В финальном решении сохранён вариант с обучением на исходных данных и исправлением кодировки только перед инференсом.

Для снижения потребления видеопамяти использовались gradient accumulation и gradient checkpointing.
Итоги
Лучший результат на Public Leaderboard составил 0.960620 NDCG@10.
Основное улучшение качества было получено при переходе от BGE Reranker к Jina Reranker. Дополнительный прирост обеспечило исправление повреждённой кодировки тестовых текстов.
При этом для восстановления кодировки не использовались метки релевантности тестовой выборки. Обработка выполнялась только на основе содержимого текстов.
В итоговом ноутбуке оставлен финальный пайплайн обучения и инференса.
